# Deploy on Render (free tier)

`render.yaml` creates one Docker web service (`workwise-api`) and one free Postgres
database (`workwise-db`).

## Steps

1. Push the repository to GitHub.
2. In Render choose **New > Blueprint**, pick the repository and apply `render.yaml`.
3. When asked for `CORS_ORIGINS`, enter your front end's origin, or leave it empty.
4. Wait for the deploy. Open `https://<service>.onrender.com/docs` and
   `https://<service>.onrender.com/ready`.

The container runs `python -m scripts.database.migrate` before starting the server, so
the schema is created on first start and updated on every deploy. `JWT_SECRET` is
generated by Render. Database settings come from the linked database.

## Create the first admin

The free plan has no shell. Run the command from your own computer against the
database's **external** connection details (Render dashboard, database page). Export
`DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `MIGRATION_DB_USER`,
`MIGRATION_DB_PASSWORD` and a 32+ character `JWT_SECRET` in your terminal, then:

    python -m workwise.cli.manage_users create-admin <username>

The external connection may require SSL (`PGSSLMODE=require`). Never commit these values.

## Free tier limits

- The service sleeps after 15 minutes without requests. The first request afterwards
  takes about a minute.
- The free database is deleted 30 days after creation and has no backups. Use it for
  demos, then recreate it or move to a paid database.
- 512 MB RAM and a shared CPU.

## Not verified

This blueprint has not been deployed. Check these on the first deploy:

- `TRUSTED_PROXIES` covers Render's proxy. If it does not, every visitor shares one
  rate-limit budget (300 requests per minute), which is safe but strict.
- The `GRANT` statements in the migration script run as the database owner and
  succeed even though the runtime and migration users are the same.
